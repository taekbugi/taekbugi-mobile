# 택배사 분석 노트

택배사 조회 방식을 **직접 분석한 기록**입니다. 레시피는 이 기록만을 근거로 처음부터 작성합니다.

## 클린룸 규칙 (라이선스)
- **delivery-tracker(shlee322, Elastic License 2.0)의 코드·구조·셀렉터·상태 매핑을 보거나 옮기지 않습니다.** 분석 중 검색 결과로 해당 저장소가 나오면 열지 않습니다.
- 다른 오픈소스 택배 조회 코드도 라이선스를 확인하기 전에는 참고하지 않습니다.
- 근거는 택배사 공개 조회 페이지를 브라우저 개발자 도구로 직접 관찰한 결과, 공공데이터포털 공식 문서뿐입니다.

## 파일 형식: `docs/carriers/<carrier-code>.md`
```
# <택배사 이름> (`<code>`)
- 분석일: YYYY-MM-DD · 분석자: (에이전트/사람)
- 조회 진입 URL, 허용 도메인
- 요청 순서: 1) GET … (쿠키·토큰 획득) 2) POST … (파라미터 이름만, 실제 송장번호 기록 금지)
- 응답 형식: JSON / HTML, 필요한 필드 경로·셀렉터
- 상태 코드 매핑: 원본 코드/문구 → DeliveryStatus
- 버릴 필드: 기사 전화번호, 수령인 이름, 상세 주소 (위치는 시·구까지만 남김)
- 송장번호 규칙: 자릿수, 체크섬(공개 출처가 있으면 출처)
- 차단 신호: 403, 캡차, 요청 제한 관찰 내용
- 골든 샘플 목록: shared/data/src/commonTest/resources/golden/<code>/…
```
