# 기획 ↔ 디자인 불일치 목록

> **규칙:** 기획에만 있거나 디자인에만 있는 내용은 **추측해서 구현하지 않습니다.** 작업을 멈추고 이 표에 기록한 뒤 사용자에게 보고합니다.
> 사용자가 결정하면 `결정` 칸을 채우고 상태를 `RESOLVED`로 바꿉니다. 결정 전 항목에 걸린 기능은 `BLOCKED_GAP`입니다.
>
> 기준: 기획서 v3.1 ([`mvp-spec.md`](mvp-spec.md)) · 디자인 캔버스 2026-11-23 판 ([`../design/README.md`](../design/README.md))

## 새 불일치를 찾았을 때

1. 위 표에 다음 번호로 한 줄 추가 (위치, 디자인 쪽 내용, 기획 쪽 내용, 막히는 기능, `OPEN`)
2. 해당 기능 명세(`docs/features/F-XX-*.md`)의 "불일치" 칸에 ID 기록, 백로그 상태를 `BLOCKED_GAP`으로
3. 작업을 멈추고 사용자에게 **무엇이 다르고 어떤 선택지가 있는지** 보고
4. 불일치와 무관한 부분만 계속 진행할 수 있는지도 함께 물어봄 (임의로 진행하지 않음)
