## 0. 디자인 기준 확정 사항

| 항목 | 확정 내용 |
|---|---|
| 비로그인 사용 | **없음 — 로그인 필수.** 온보딩은 Apple / 카카오 / 이메일로 시작 |
| 로그인 전 드래그·공유 등록 | 디자인에 해당 화면 없음 → 송장번호를 **임시 보관 큐**(App Group 공유 저장소 / 로컬 DB)에 넣고, 로그인 완료 후 자동 등록. 공유 확장·PROCESS_TEXT 화면에서 로그인 화면을 직접 띄우지 않음 |
| 택배사 후보 직접 선택 | **Android 등록 화면에만 제공.** iOS 공유 확장은 자동 판별만 (후보가 여럿이면 조회 결과가 나오는 택배사를 채택) |

> 로그인 전 등록 시 안내 문구나 화면이 필요하면 디자인에 추가 요청

## 1. 컨셉

- **택부기 – 드래그하면 추적되는 택배 위젯**
- 택배 상자를 등껍질처럼 짊어진 거북이 캐릭터가 택배를 대신 지켜봄
- 어디서든 송장번호를 드래그(선택)하면 택배사를 판별해서 자동 등록하고, 위젯에서 진행 상황을 보여줌
- 계정으로 **"내 택배"**를 관리하고, 기기를 바꿔도 목록 유지

### 이번 범위에서 제외
월별 결산, 유료 플랜(직구 패키지·꾸미기·가족 공유), 해외 택배 추적 → MVP 이후 검토

## 2. MVP 기능

| # | 기능 | 내용 |
|---|---|---|
| 1 | 드래그로 등록 | 텍스트를 선택하면 송장번호를 추출하고 택배사를 판별해서 등록 |
| 1-1 | 택배사 후보 직접 선택 | 판별 후보가 여럿이면 사용자가 선택 (**Android 등록 화면**, iOS는 자동 판별만) |
| 2 | 자동 추적 | 상태별로 조회 주기를 조절 |
| 3 | 위젯 | 상태별 **라인 아이콘 + 상태 칩 색** + 택부기 연출(9장) |
| 4 | 내 택배 | 계정 기반 목록 관리 (진행 중 / 완료, **별칭**), 기기 간 동기화 |
| 4-1 | 내 택배에서 삭제 | 택배 상세 화면 하단 |
| 4-2 | 완료 택배 정리 | 배송 완료 후 **[N]일** 지나면 자동 정리 (설정에서 변경) |
| 5 | 조회 지연 알림 | 사용자에게 알리는 기능 (설정에서 켜고 끄기) |
| 6 | 이슈 감지 | 서버 모니터링용 레시피 실패율 알림 (7장, 운영자 대상) |
| 7 | 스플래시 | 12월 산타 스킨 스위치 포함 |

> 이모지는 전부 제거 (위젯 택배사 이모지, 내 택배 이모지, 등록 화면 이모지 선택기)

### 배송 상태 표시
| 상태 | 라인 아이콘 | 상태 칩 |
|---|---|---|
| 집하 전 | 시계 | 디자인 시안의 상태 칩 색 기준 |
| 이동 중 | 상자 | 〃 |
| 배송 출발 | 트럭 | 〃 |
| 배송 완료 | 체크 | 〃 |

### 플랫폼별 입력 방식
| | Android | iOS |
|---|---|---|
| 드래그(텍스트 선택) | ✅ `ACTION_PROCESS_TEXT` → 선택 메뉴에 **"택배 추적"** 바로 표시 | ⚠️ 시스템 선택 메뉴에 항목 추가 불가 → 선택 → **공유 → 공유 확장**으로 등록 (앱 실행 없음) |
| 보조 수단 | 앱 실행 시 클립보드 감지 | 앱 실행 시 `detectPatterns`로 클립보드 감지 + `UIPasteControl`, 뒷면 탭 단축어 |

### 조회 주기 (상태별)
| 상태 | 주기 |
|---|---|
| 집하 전 | 6시간 |
| 이동 중 | 2시간 |
| 배송 출발 | 30분 |
| 배송 완료 | 조회 중지 → **[N]일** 후 정리 |

- Android: WorkManager (최소 15분), 위젯 갱신
- iOS: WidgetKit 타임라인 + 서버의 조용한 푸시로 앱을 깨워 조회

### 조회 지연 알림 (신규)
- 7장 이슈 감지(운영자용)와 **별개의 사용자용 기능**
- 앱이 직접 조회하므로 **기기에서 판단해서 로컬 알림**으로 발송
- 알림 조건(초안, 확정 필요)
  - 같은 상태에서 일정 시간 이상 변화 없음 (예: 이동 중 48시간)
  - 조회 실패가 연속으로 발생
- iOS는 백그라운드 조회가 깨어나야 판단 가능 → 조용한 푸시 주기와 연동

### 완료 택배 정리 (신규)
- 설정 항목: 배송 완료 후 **[N]일** 지나면 정리 (기본값 확정 필요)
- 정리 = 목록에서 숨김(`archived_at`) 또는 삭제 — 방식 확정 필요
- 서버 동기화 시 다른 기기에도 같은 상태 반영

### 내 택배에서 삭제 (신규)
- 택배 상세 화면 하단
- 서버의 Parcel·TrackEvent 삭제 + 다른 기기 동기화를 위한 **삭제 기록(tombstone)** 유지

## 3. 아키텍처

### 기술 스택
| 영역 | 선택 |
|---|---|
| 공유 로직 | **Kotlin Multiplatform** (Ktor, Ksoup, kotlinx.serialization, kotlinx-datetime) |
| Android | Jetpack Compose + **Glance** 위젯 |
| iOS | SwiftUI(또는 Compose Multiplatform) + **WidgetKit** + Share Extension |
| 백엔드 | **Django** (DRF 또는 Django Ninja) + PostgreSQL |
| 메일 발송 | 이메일 코드 로그인용 발송 수단 (예: AWS SES 등) |
| 모니터링 | Prometheus + **Grafana** |

### 데이터 흐름
```
[앱] 송장 등록 → 택배사 페이지 직접 조회 (서버 드리븐 레시피)
    → 정규화된 결과를 로컬 DB에 저장
    → [서버] 내 택배 동기화 + 성공/실패 지표 보고
```
- 택배사 조회는 **사용자 폰에서만** 수행 (서버는 조회하지 않음)
- 서버로는 정규화된 최소 필드만 전송

### KMP 모듈 구조
```
shared/ (commonMain)
 ├─ recipe/   레시피 JSON 모델 + 해석기
 ├─ carrier/  택배사 메타, 송장번호 패턴(자릿수·체크섬), 후보 판별
 ├─ domain/   Parcel, TrackEvent, 공통 상태 코드
 ├─ sync/     서버 API 클라이언트 (인증, 동기화, 지표)
 ├─ alert/    조회 지연 판단 로직
 └─ storage/  로컬 DB, 로그인 전 임시 보관 큐
androidApp/   Compose 앱 + Glance 위젯 + PROCESS_TEXT 액티비티
iosApp/       SwiftUI 앱 + WidgetKit 확장 + Share Extension
```
- iOS: shared를 **정적 프레임워크**로 빌드해서 앱·위젯 확장·공유 확장에 링크

## 4. 택배사 데이터

| 택배사 | 방식 |
|---|---|
| 우체국 | 공공데이터포털 API (무료, 자동승인) |

- 송장번호는 자릿수와 체크섬으로 후보 택배사를 먼저 좁힌 뒤 조회
- 후보가 여럿이면 사용자가 선택 (2장 1-1)

## 5. 서버 드리븐 레시피

- 서버가 **선언형 레시피(JSON)**를 내려주고 앱이 해석 (코드 다운로드·실행 아님)
- 레시피만 다시 배포해서 택배사 사이트 개편에 대응
- 안전장치
  - **Ed25519 서명** (비밀키는 CI·로컬에서만, 앱에는 공개키)
  - **택배사 도메인 허용 목록**을 앱에 내장
  - `min_interpreter_version`으로 구버전 앱 호환
  - 마지막으로 성공한 레시피 캐시
  - canary → active 단계적 배포
  - 골든 테스트 (응답 샘플은 개인정보 마스킹)

## 6. 백엔드 (Django)

### 모델
```python
User                  # 로그인: Apple + 카카오 + 이메일(코드 인증)
LoginCode             # 이메일 코드 (allauth 코드 로그인 사용 시 대체)
ConsentRecord         # user FK, term_type, term_version, required, agreed, agreed_at
UserSettings          # delay_alert_enabled, archive_after_days(N)
Carrier               # code, name, domain_allowlist
Recipe                # carrier FK, version, spec(JSON), signature, rollout(canary/active)
Parcel                # user FK, carrier FK, carrier_source(auto/user),
                      # tracking_hmac, tracking_ciphertext,
                      # nickname, status, delivered_at, archived_at
ParcelTombstone       # user FK, tracking_hmac, deleted_at  (삭제 동기화용)
TrackEvent            # parcel FK, status(정규화), raw_code, occurred_at, location(시·구 단위까지만)
RecipeRun (지표)      # Prometheus 카운터로 집계, DB 저장은 선택
```
- `Carrier.emoji`, `Parcel.emoji` **제거**
- `carrier_source`: 자동 판별인지 사용자 선택인지 기록 → 판별 정확도 개선 지표로 활용

### 로그인
| 방식 | 비고 |
|---|---|
| Sign in with Apple | 카카오 로그인이 있는 한 **필수** (현재 충족) |
| 카카오 | |
| 이메일(코드 인증) | 신규. 아래 요건 참고 |
| ~~구글~~ | 디자인에서 제외 |

#### 이메일 코드 로그인 요건
- **메일 발송 수단** 필요 (발송 도메인 SPF·DKIM 설정 포함)
- 코드: 6자리, **만료 시간**(예: 10분), 서버에는 해시로 저장
- **재전송 제한**(예: 60초 쿨다운, 시간당 횟수 제한)
- **시도 횟수 제한**(예: 5회 실패 시 코드 무효화)
- 이메일·IP 단위 요청 제한
- allauth를 쓰면 **코드 로그인 기능**으로 처리 가능

### 송장번호 저장
| 필드 | 용도 |
|---|---|
| `tracking_hmac` | 서버 비밀키를 섞은 HMAC — 중복 확인과 검색 |
| `tracking_ciphertext` | 앱에서 암호화한 원문 — 새 기기에서 복원 후 재조회 (키는 iCloud 키체인 / Android Block Store, 서버는 원문 열람 불가) |

> 단순 해시는 10~13자리 숫자라 전수 대입으로 뒤집힘 → 사용 금지

### 계정
- dj-rest-auth 또는 allauth + SimpleJWT
- **앱 안에서 계정 삭제** 필수 → Parcel, TrackEvent, ConsentRecord 등 cascade 삭제
- **로그인 필수** (비로그인 사용 없음)
- 로그인 전 드래그·공유로 들어온 송장은 임시 큐에 보관 → 로그인 직후 등록 (`tracking_hmac`으로 중복 제거)

### 약관 동의
- 이메일 가입에 약관 동의 단계 포함
- **동의 내역 저장**: 항목, 약관 버전, 시점, 필수/선택 여부, 동의 여부 (`ConsentRecord`)
- 약관이 개정되면 새 버전으로 재동의를 받을 수 있게 버전 관리

### 기타
- `status`는 정규화 코드와 `raw_code`를 함께 저장
- TrackEvent에 기사 전화번호, 수령인 이름 저장 금지
- 지표 API는 인증 사용자만, 사용자별 요청 제한

## 7. 이슈 감지 (Grafana)

> 운영자용 서버 모니터링. 사용자용 "조회 지연 알림"(2장)과는 별개.

```
recipe_runs_total{carrier, version, result, step}
```
- 라벨에 사용자 ID, 앱 버전 등 고카디널리티 값 금지
- **실패율 기준** 알림: 택배사별 15분 실패율 > 30% **그리고** 조회 ≥ 20건
- 레시피 배포 후 버전별 실패율 급증 감지 (추후 자동 롤백)

| 수준 | 조건 | 의미 |
|---|---|---|
| warn | 매핑에 없는 상태 코드 | 택배사가 새 상태 추가 |
| critical | 요청 실패·셀렉터 미스 급증 | 사이트 개편 |
| block | 403·캡차 응답 | 차단 신호 |

- 알림 채널: 슬랙 / 디스코드 / 텔레그램, 실패한 `step` 포함

## 9. 브랜드 — 택부기

### 이름
- **택부기** = 택배 + 거부기(거북이의 친근한 표현)
- 스토어 표기: **"택부기 – 드래그하면 추적되는 택배 위젯"**
  - 이름에 "택"이 들어가고 부제에 "택배 위젯"이 있어서 검색 신호 확보
- 웹 검색상 같은 이름의 서비스는 확인되지 않음 (상표 검색은 별도 필요)

### 디자인 톤
- 화면: **흰 톤 + 그림자 + 올리브 그린 포인트 컬러 하나**로 차분하게
- 귀여운 느낌은 **캐릭터 일러스트가 담당**
- 이모지 미사용 → 배송 상태는 라인 아이콘과 상태 칩 색으로 표현

### 캐릭터
- 택배 상자를 **등껍질처럼 짊어진 거북이**
- 디자인 원칙: **꼬부기 연상 피하기**
  - ❌ 파란 몸통, 말린 꼬리, 꼬부기식 등껍질 모양
  - ✅ 등껍질 = 테이프 붙은 **크래프트 박스**
  - ✅ 몸 색은 연두·올리브 계열 (포인트 컬러와 맞춤)

### 상태별 연출 (위젯·Live Activity)
| 배송 상태 | 택부기 |
|---|---|
| 집하 전 | 상자 옆에서 꾸벅꾸벅 조는 중 |
| 이동 중 | 상자 메고 걸어가는 중 |
| 배송 출발 | **스케이트보드** 타고 질주 (반전 포인트) |
| 배송 완료 | 문 앞에 상자 내려놓고 손 흔들기 |
| 조회 실패·지연 | 갸우뚱하며 지도 보는 중 |

### 톤 & 카피
- "거북이 = 느림" 이미지를 역이용 (디자인에서도 유지)
  - "느긋하게 기다려요, 택부기가 대신 지켜볼게요"
  - "드래그만 하세요, 나머지는 택부기가"
- 시즌 스킨: 12월에는 산타 모자 택부기 — **스플래시 화면에 스위치** 포함
