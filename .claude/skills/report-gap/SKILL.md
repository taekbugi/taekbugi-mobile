# 불일치 기록·보고

1. `docs/product/spec-design-gaps.md`를 읽고 같은 내용이 이미 있는지 확인합니다. 있으면 그 ID를 씁니다.
2. 없으면 표 끝에 새 행 추가: `G-NN | 위치(화면 파일) | 디자인 쪽 내용 | 기획 쪽 내용(절 번호, 없으면 "없음") | 막히는 기능 | OPEN | (빈칸)`
3. 관련 기능 명세의 "불일치·미정"에 ID 추가, `docs/features/backlog.md`의 막힘 칸에 ID 추가하고 상태를 `BLOCKED_GAP`으로.
4. **작업을 멈추고** 보고합니다 (하위 에이전트면 결과 첫 줄 `STOP:`). 보고 형식:

```
STOP: 기획↔디자인 불일치 G-NN
- 무엇: (한 줄)
- 디자인: <화면 링크> — (보이는 내용)
- 기획: mvp-spec.md §N — (내용 또는 "언급 없음")
- 선택지: A) … B) … C) 디자인 수정 요청
- 추천: … (이유 한 줄)
- 불일치와 무관하게 계속할 수 있는 부분: …(진행 여부는 사용자 결정)
```

5. 사용자가 결정하면 `결정` 칸에 날짜와 내용을 적고 상태를 `RESOLVED`로 바꿉니다. 결정이 기획 변경이면 기획서 원문은 고치지 않고 결정 칸이 우선한다고 적습니다.
