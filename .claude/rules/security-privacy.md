# 보안·개인정보·라이선스 규칙 (항상 적용)

## 개인정보
- 송장번호·이메일·인증 토큰은 개인정보로 취급합니다. 로그·크래시 리포트·분석 이벤트·스크린샷에 원문 금지 (마스킹 `6087****5678`).
- 택배사 응답에서 **기사 전화번호, 수령인 이름, 상세 주소는 파싱 단계에서 버립니다.** 위치는 시·구 단위까지만 저장합니다.
- 서버로 보낼 데이터는 API 문서 이후에 정하되, 기획 원칙(정규화된 최소 필드, 송장번호 원문은 클라이언트 암호문으로만)을 지킵니다. 단순 해시는 쓰지 않습니다.
- 테스트·골든 샘플·QA 보고서에는 가짜 값만 씁니다.

## 레시피 안전장치
- Ed25519 서명 검증을 통과한 레시피만 실행합니다. 서명 비밀키는 저장소·앱에 절대 넣지 않습니다(공개키만 내장).
- 요청은 앱에 내장된 택배사 도메인 허용 목록 안의 HTTPS만. 레시피가 허용 목록을 넓힐 수 없습니다.
- 레시피는 선언형 데이터입니다. 스크립트·코드 실행 기능을 해석기에 넣지 않습니다.

## 라이선스 (클린룸)
- **delivery-tracker(shlee322, Elastic License 2.0)의 코드·구조·셀렉터·매핑을 보거나 옮기지 않습니다.** 레시피는 택배사 페이지를 직접 분석해서 처음부터 작성하고 `docs/carriers/`에 근거를 남깁니다.
- 새 외부 라이브러리는 라이선스를 확인하고 ADR에 적습니다.

## 비밀 값
- `local.properties`, `.env`, `*.keystore`, `*.jks`, `*.p8`, `*.mobileprovision`, API 키를 커밋하지 않습니다. 읽지도 않습니다(필요하면 사용자에게 요청).
- 키가 없으면 빌드·실행이 분명한 오류로 실패하게 만듭니다. 기본값으로 가짜 키를 넣지 않습니다.

## 심사·브랜드
- 택배사 로고 미사용, 공식 앱처럼 보이는 표현 금지(5.2.2). 캐릭터는 꼬부기 연상 요소(파란 몸통, 말린 꼬리, 꼬부기식 등껍질) 금지.
