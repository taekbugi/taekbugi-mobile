# 멈추고 보고하는 규칙 (항상 적용)

아래 경우에는 **추측해서 진행하지 않고 작업을 멈춘 뒤 사용자에게 보고**합니다. 보고에는 무엇을 발견했는지, 근거(기획서 절·디자인 화면 링크·파일 경로), 가능한 선택지와 추천 하나를 담습니다.

1. **기획과 디자인 불일치**
   - 기획에는 있는데 디자인에 없는 것 (화면, 상태, 문구, 동작)
   - 디자인에는 있는데 기획에 없는 것 (버튼, 토글, 메뉴, 표시 값)
   - 둘이 서로 다른 것
   → `docs/product/spec-design-gaps.md`에 G- 항목 추가(`/report-gap`), 기능 상태 `BLOCKED_GAP`.
   - 이미 `OPEN`인 G- 항목에 걸린 부분도 같은 취급입니다. "디자인이 정본"이라는 문장을 근거로 디자인에만 있는 기능을 만들지 않습니다.
2. **백엔드 API가 필요한 작업**인데 `docs/api/specs/`가 비어 있을 때 (ADR-0006)
3. `docs/product/open-questions.md`의 미정 항목에 걸릴 때
4. 디자인 에셋(캐릭터 일러스트·로고)이 필요한데 없을 때 — 자리 표시 컴포넌트까지만 만들고 보고
5. 되돌리기 어려운 결정(`Proposed` ADR, 새 외부 라이브러리, 권한 추가, 패키지명)
6. 수정 → 리뷰/QA 실패 반복이 3회를 넘을 때

불일치와 무관한 부분을 계속해도 되는지는 **사용자에게 물어서** 정합니다. 하위 에이전트는 멈춘 이유를 결과 보고 맨 앞에 `STOP:`으로 적어 메인 세션에 돌려줍니다.
